# MQTT-библиотеки для CODESYS

## Вердикт: FieldFox/Codesys-Mqtt-lib — НЕ пригодна

Репозиторий: `Library/_ref/Codesys-Mqtt-lib/`. Проверено чтением исходников.

* **Платформа**: CODESYS **V2.3 / WAGO** (стиль C-интеропа: `mqtt.c`/`mqtt.h`,
  `.lib`/`.pro`, зависимости `SysLibSockets`, `WagoLibEthernet_01`,
  `oscat_basic_333`). Тестировалось на WAGO 750-881 (~2014 г.).
* **Код**: это каркас — только init-функции и константы типов пакетов MQTT.
  Тела `_BUFFER_CONCAT`, `_BUFFER_PUSH`, `CREATE_MESSAGE`,
  `ENCODE_REMAINING_LENGTH`, `MQTT_CLIENT` — **пустые** (см. `mqtt.c`).
  Полезно только как напоминание структуры фиксированного заголовка MQTT
  (message types 1..14, QoS-флаги, CONNECT-флаги).
* **Вывод**: не использовать. Не путать с рабочими решениями под V3.

## Что смотреть вместо (направления)

> Список кандидатов требует веб-проверки (БЛОК 2, следующая итерация).
> Критерии проверки: версия CODESYS ≥ 3.5 SP17, лицензия, дата коммитов,
> наличие тестов/примеров.

1. **CODESYS IoT/Connectivity**: встроенные средства CODESYS (OPC UA/REST
   готовы из коробки; MQTT — через дополнительные компоненты/библиотеки из
   Store).
2. Community-библиотеки MQTT на чистом ST (поиск: `codesys mqtt structured
   text`) — проверять покрытие QoS0/1/2, TLS, retained messages, last will.
3. Внешние шлюзы (MQTT-брокер на edge-шлюзе, PLC говорит Modbus/OPC UA) —
   архитектурная альтернатива, часто надёжнее встраивания стека в ПЛК.

## Критерии выбора MQTT-стека для ПЛК

| Критерий | Почему важно |
|---|---|
| Версия CODESYS | Библиотеки V2 не работают в V3 (внешний C-interop отличается) |
| QoS 0/1/2 | Для телеметрии хватает QoS0; для команд — минимум QoS1 |
| TLS/авторизация | IEC 62443: без шифрования в промышленную сеть не выходить |
| Keep-alive / LWT | Детект обрыва связи и «завещание» при недоступности ПЛК |
| Размер буферов | Память ПЛК ограничена; проверять лимиты payload |
| Неблокирующий цикл | Сетевые операции — асинхронно, не ронять цикл задачи |
