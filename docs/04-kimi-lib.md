# Правило 04. Работа с собственной библиотекой решений

У агента (или команды) есть самописная библиотека решений — «цифровая копия
лучших решений»: проверенные решения живут там и переиспользуются во всех
проектах. Источник истины — один файл `.library`; правится напрямую через
MCP/мост. Путь к нему задаёт пользователь при настройке области
(см. `docs/01-workflow.md`). Валидация — standalone через мост
(`validate_library`), без зеркального проекта.

## БИБЛИОТЕКА

Это «цифровая копия лучших решений»: проверенные решения живут здесь и
переиспользуются во всех проектах. Фундамент — PackML (OMAC) **в виде
vendor-библиотеки 3S** `OMAC_PackML_State_Machine` (namespace `PACK_ML`):
`PACK_ML.State` (17 состояний, битовая маска DWORD), `PACK_ML.IUnitMode`,
`PACK_ML.UnitMode`, `PACK_ML.UnitModeManager` — состояния и режимы в своей
библиотеке **не дублируются**. Над ними — собственный конфигуратор
оборудования (в референсной реализации — `EquipmentCfg`, дизайн — в
`library/README.md`):

```st
fbEq(sName := 'Dozer', xStartBtn := xBtn, xDone := xCylDone);
CASE fbEq.eCurrentState OF
    PACK_ML.State.Idle:    // waiting
    PACK_ML.State.Execute: // main cycle
END_CASE
IF fbEq.StateEntered(PACK_ML.State.Execute) THEN ... END_IF  // one-scan entry pulse
```

Недопустимая команда не рвёт цикл — взводится `xCmdRejected` на один цикл.

### Рабочий цикл с библиотекой

1. Любое изменение — через MCP (`codesys_create_pou`, `codesys_create_member`,
   `codesys_create_dut`, `codesys_set_code` и т.д.) с путём к `.library`.
2. После изменений — обязательная валидация через мост `validate_library`
   (компиляция `.library` через `check_all_pool_objects()`, standalone без зеркала).
   Критерий: «0 ошибок, 0 предупреждений».
3. После каждого изменения — **обновить README библиотеки**: +строка в «Историю версий»,
   +объект в «Состав» (для нового). Документация обязательна, без неё изменение
   не считается завершённым.

### Пополнение библиотеки

**Агент вправе сам пополнять библиотеку**, если решение:

* решает типовую задачу, которая встретится в других проектах (не разовый кейс);
* проходит валидацию (`validate_library`) с 0 ошибок, 0 предупреждений;
* соблюдает паттерн «код под состоянием» и стандарты (`docs/07-standards.md`);
* не имеет лишних внешних зависимостей (зависимости фиксируются явно).

### Запрет самопроизвольного удаления и переписывания

* **Удалять или полностью переписывать существующие блоки библиотеки агент НЕ вправе.**
  Только по явной команде пользователя («удали блок X», «перепиши блок Y») — и только
  указанный блок (через мост `delete_object` / `set_code`), соседние не трогать.
* Мелкие правки существующего блока (багфикс, расширение) допустимы, но должны быть
  перечислены в отчёте и задокументированы в README библиотеки (история версий).
* В отчёте пользователю явно перечисляй: что добавлено/изменено в библиотеке и почему.

## Подключение библиотеки к проекту

Через Library Manager проекта, **без копирования объектов в проект**:
библиотека используется как `<Namespace>.<Имя>`.

1. Установить библиотеку в репозиторий библиотек CODESYS
   (`librarymanager.insert_repository` + `lib_install` с `overwrite=True`).
2. `lib_add` в проект → ссылка в Library Manager; namespace задаётся
   явно (`setattr(reference, 'namespace', '<Namespace>')`).
3. Сборка проекта: `build` → 0 ошибок, 0 предупреждений.

Нюансы (проверено на SP21 Patch 1): `find_library` ищет по полному display
name библиотеки; `insert_repository` в живой сессии поднимает «уже
существует» — действует со следующего старта демона.
