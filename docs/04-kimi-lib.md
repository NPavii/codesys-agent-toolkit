# Правило 04. Работа с библиотекой Kimi_Lib

Источник истины: `Library/CoDeSyS_Lib/Kimi_Lib.library` (правится напрямую
через MCP/мост). Валидация — standalone через мост (`validate_library`),
без зеркального проекта.

## БИБЛИОТЕКА Kimi_Lib

Самописная библиотека: `Library/CoDeSyS_Lib/Kimi_Lib.library` — **источник истины**
(файл `.library`, открывается и правится через MCP напрямую). Это «цифровая копия лучших
решений»: проверенные решения живут здесь и переиспользуются во всех проектах.
Фундамент — PackML (OMAC): `State` (17 состояний, битовая маска DWORD), `IUnitMode`,
`UnitMode`, `UnitModeManager`, `GVL_Constants`, и наш конфигуратор `EquipmentCfg`:

```st
fbEq(xStart := xBtn, xDone := xCylDone);   // фронтовые команды
CASE fbEq.eCurrentState OF
    State.Idle:    // waiting
    State.Execute: // main cycle
END_CASE
IF fbEq.StateEntered(State.Execute) THEN ... END_IF  // one-scan entry pulse
```

Недопустимая команда не рвёт цикл — взводится `xCmdRejected` на один цикл.

### Рабочий цикл с библиотекой

1. Любое изменение — через MCP (`codesys_create_pou`, `codesys_create_member`,
   `codesys_create_dut`, `codesys_set_code` и т.д.) с путём к `Kimi_Lib.library`.
2. После изменений — обязательная валидация через мост `validate_library`
   (компиляция `.library` через `check_all_pool_objects()`, standalone без зеркала).
   Критерий: «0 ошибок, 0 предупреждений».
3. После каждого изменения — **обновить `Library/README.md`**: +строка в «Историю версий»,
   +объект в «Состав» (для нового). Документация обязательна, без неё измение не считается завершённым.

### Пополнение библиотеки

**Агент вправе сам пополнять библиотеку**, если решение:

* решает типовую задачу, которая встретится в других проектах (не разовый кейс);
* проходит валидацию (`validate_library`) с 0 ошибок, 0 предупреждений;
* соблюдает паттерн «код под состоянием» и стандарты выше;
* не имеет внешних зависимостей (библиотека самодостаточна: без Standard и прочих lib).

### Запрет самопроизвольного удаления и переписывания

* **Удалять или полностью переписывать существующие блоки библиотеки агент НЕ вправе.**
  Только по явной команде пользователя («удали блок X», «перепиши блок Y») — и только
  указанный блок (через мост `delete_object` / `set_code`), соседние не трогать.
* Мелкие правки существующего блока (багфикс, расширение) допустимы, но должны быть
  перечислены в отчёте и задокументированы в `Library/README.md` (история версий).
* В отчёте пользователю явно перечисляй: что добавлено/изменено в библиотеке и почему.

## Подключение Kimi_Lib к проекту (проверено 2026-09-20)

Через Library Manager проекта, **без копирования объектов в проект**:
библиотека используется как `Kimi_Lib.<Имя>` (namespace).

1. Репозиторий `Kimi` → `Library/_repo` (создан через
   `librarymanager.insert_repository`). Библиотека установлена туда:
   `lib_install` с `overwrite=True`.
2. `lib_add` в проект → ссылка в Library Manager; namespace принудительно
   `Kimi_Lib` (`setattr(reference, 'namespace', 'Kimi_Lib')`).
3. Сборка проекта: `build` → 0 ошибок, 0 предупреждений.

Нюансы: внутренний Title библиотеки пока «Основная библиотека» (company My,
версия 0.0.1) — `find_library` ищет по полному display name; namespace при
этом всё равно задаётся `Kimi_Lib`. `insert_repository` в живой сессии
поднимает «уже существует» — действует со следующего старта демона.

## Как подключить библиотеку к проекту

1. Открыть целевой проект в CODESYS.
2. Вариант А (источник): добавить POUs библиотеки копированием из `Kimi_Lib.library`.
3. Вариант Б (бинарник): `Project → Save as compiled library...` поверх `Kimi_Lib.library`,
   полученный файл положить в репозиторий — далее подключать через Library Manager
   как обычную библиотеку.
